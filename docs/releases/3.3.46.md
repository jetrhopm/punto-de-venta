# JetVenta 3.3.46 - Endurecimiento de cobros Mercado Pago Point

## Objetivo

Cerrar las rutas que permitían registrar pagos con tarjeta sin comprobar una aprobación de Point en la caja configurada.

## Cambios previstos

- La venta validará la configuración activa de Point de la caja, no el indicador histórico de la tienda.
- El cajero podrá conocer si Point aplica a su caja mediante un endpoint de consulta sin acceso a configuración.
- Cada intento de tarjeta tendrá un identificador propio, vinculado al identificador estable del ticket. Los rechazos, vencimientos y cancelaciones podrán reintentarse sin reutilizar la orden anterior.
- Una orden aprobada deberá coincidir exactamente con el importe que se intenta cobrar.
- Estados aún conciliables no se tratarán como finales; la consulta tendrá reintentos antes de mostrar una revisión manual.
- La cancelación informará el resultado real y no declarará éxito cuando la API no lo confirme.
- Tokens de prueba aceptarán únicamente el prefijo de sandbox `TEST-`.
- La orden Point no limitará la terminal a crédito; al no enviar un tipo por defecto, Mercado Pago permite los medios compatibles de la terminal, incluido débito.

## Límites deliberados

- No se automatiza un reembolso hasta confirmar el endpoint y reglas oficiales de Mercado Pago para Point. Esta versión bloquea cancelar o devolver una venta Point antes de modificar inventario o caja; nunca aparenta que devolvió dinero.
- El callback OAuth y webhook público requieren un gateway HTTPS central o una alternativa oficial de Mercado Pago. La API LAN de una tienda no se expondrá a Internet como solución temporal.
