# Plan 2.5.10 - Permisos, autorización y catálogos operativos

## Base y retorno

- Base funcional: `v2.5.9`.
- No se modifica ni elimina ningún tag desde `v2.5.5` hasta `v2.5.9`.
- Antes de cada bloque se revisará el diff y, al completarlo, se creará un commit y tag `v2.5.10` solamente cuando toda la versión esté validada.
- Si un bloque requiere separarse por riesgo, se creará primero un commit de trabajo documentado sin mover o reemplazar tags previos.

## Hallazgos que atiende

- Las notas de pruebas `5.7`, `5.8`, `5.10` y `5.11` indican que el cajero recibe bloqueos poco claros, que producto común solicita permiso antes de elegir la acción y que la autorización temporal no explica credenciales inválidas ni permisos insuficientes.
- Las observaciones de usuarios, clientes y departamentos piden flujos visibles para administrar cada catálogo y evitar que un cajero modifique configuración sensible.
- Los fallos históricos de tickets, corte y cierre de sesión obligan a probar que el trabajo de permisos no altere ventas, turnos ni caja.

## Bloque A: perfiles y permisos de cajero

1. Revisar el conjunto de permisos actual y su punto de evaluación en cada acción.
2. Definir permisos predeterminados de cajero: vender, buscar productos, cobrar, consultar sus tickets y operar acciones propias de caja autorizadas; sin configuración, administración de usuarios, catálogos, diagnósticos ni cambios de negocio.
3. Al crear administrador, activar todos los permisos aplicables; al crear cajero, usar el perfil base anterior y permitir ajustes explícitos.
4. Mantener los permisos ya otorgados a usuarios existentes: no se revocarán ni concederán de forma automática durante la actualización.

**Criterio:** un cajero vende normalmente, pero las acciones administrativas permanecen bloqueadas con una explicación útil.

## Bloque B: autorización temporal

1. Cuando falte un permiso, mostrar una alerta que diga qué acción se solicitó y qué permiso debe aprobarse.
2. Mostrar usuarios activos seleccionables y solicitar sólo contraseña; conservar filtro por nombre cuando haga falta.
3. Distinguir visualmente tres resultados: contraseña incorrecta, usuario inactivo y usuario que no posee el permiso solicitado.
4. Conceder la autorización sólo para la acción actual. No cambiar permisos persistentes, sesión de caja ni usuario conectado.
5. Cancelar con `Esc`; confirmar con `Enter`; usar el diseño de alertas acordado.

**Criterio:** un administrador puede aprobar una acción puntual sin dejar privilegios abiertos para operaciones posteriores.

## Bloque C: producto común y producto permanente

1. Al no encontrar un código, primero permitir elegir entre `Producto común (temporal)` y `Registrar producto`.
2. Producto común no exige permiso de administrar catálogo: se agrega sólo al ticket, mantiene trazabilidad para devoluciones y no aparece en inventario.
3. Registrar producto sí exige el permiso de catálogo y conserva el código obligatorio.
4. El diálogo temporal conservará datos prácticos: nombre predeterminado, unidad/granel, cantidad y precio; no debe abrir un segundo diálogo de cantidad para ese mismo flujo.
5. Mantener el flujo existente de cantidad para artículos de inventario por peso o granel.

**Criterio:** el cajero resuelve un artículo no registrado en una sola ventana, mientras que el inventario sólo cambia mediante el flujo permanente autorizado.

## Bloque D: clientes

1. Diferenciar Clientes de Créditos: Clientes administra datos y estado; Créditos consulta y cobra saldos.
2. Convertir altas, edición y baja lógica en diálogos claros; doble clic abre edición.
3. La baja lógica conserva ventas, créditos, reportes y devoluciones históricas.
4. Aplicar permisos concretos para crear, editar o desactivar, sin impedir consultar clientes durante una venta cuando corresponda.

**Criterio:** se administra el catálogo de clientes sin confundirlo con el flujo financiero de créditos ni perder historial.

## Bloque E: departamentos

1. Mantener la normalización de importación introducida en `v2.5.9`.
2. Mostrar y permitir asignar departamento desde Productos F3 e Inventario F4.
3. Crear, editar y desactivar departamentos con validación de nombres y baja lógica.
4. Impedir departamentos duplicados sin distinguir mayúsculas, minúsculas ni acentos en los flujos de catálogo nuevos.

**Criterio:** el departamento visible en F3, F4, reportes y exportación corresponde al mismo catálogo real.

## Pruebas de regresión obligatorias

1. Administrador y cajero: crear ticket con `F6`, agregar producto, cobrar y confirmar venta.
2. Cajero sin permiso: intentar una acción restringida, cancelar autorización y comprobar que no cambia nada.
3. Administrador: autorizar una sola acción temporal; repetirla y confirmar que vuelve a requerir autorización.
4. Cerrar sesión, volver a iniciar y verificar que la autorización temporal no persiste.
5. Abrir y cerrar turno/caja con permisos respectivos sin afectar tickets activos.
6. Producto común, producto permanente, producto por peso/granel y búsqueda por lector/Enter.
7. Cliente y departamento: crear, editar, desactivar y confirmar conservación del historial.

## Fuera de alcance

- Multicaja, dispositivos físicos, Mercado Pago, recargas y licenciamiento no se modificarán en esta versión.
- No se rediseñan tickets, cobros, importación/exportación ni reglas de corte salvo que una prueba demuestre una dependencia real.
