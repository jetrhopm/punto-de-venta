# JetVenta 3.3.6 - Instalador por modalidad de caja

## Objetivo

Permitir instalar una caja principal completa o una caja adicional de red con
el mismo `Setup.exe`, sin que las cajas adicionales instalen infraestructura de
servidor.

## Implementado

- En instalación nueva, el instalador muestra dos modalidades claras:
  **Caja principal / servidor** y **Caja adicional**.
- La caja principal conserva PostgreSQL, API, servicios de Windows y regla de
  Firewall privada, además del escritorio y Visual C++.
- La caja adicional instala sólo JetVenta y Visual C++; filtra API, PostgreSQL,
  scripts de instalación de servidor y no ejecuta operaciones sobre servicios
  ni Firewall.
- La caja adicional solicita dirección, puerto, código temporal y nombre de
  caja; valida salud del servidor y protocolo LAN antes de emparejarse.
- Al emparejarse, guarda URL, caja, dispositivo y token protegido con DPAPI de
  máquina en el perfil compartido del equipo.
- La modalidad se persiste en `installation-mode.json`. Las actualizaciones no
  vuelven a preguntar ni cambian una caja adicional a servidor.
- Un emparejamiento incompleto queda marcado como pendiente para permitir
  reintentar con un código nuevo sin instalar PostgreSQL por accidente.
- El arranque remoto ya no intenta iniciar o reparar API/PostgreSQL local cuando
  una caja adicional no puede contactar a su servidor.

## Compatibilidad

- Requiere servidor y caja con protocolo LAN `2` o superior compatible.
- Instalaciones previas sin modalidad persistida se tratan como caja principal.
- No requiere migración de base de datos ni modifica ventas, inventario,
  sesiones o periféricos.

## Pruebas manuales recomendadas

1. Instalar en una computadora limpia como caja principal y confirmar servicios,
   PostgreSQL, Firewall y API local.
2. Generar un código temporal desde la principal; instalar otra computadora como
   caja adicional, indicar IP/puerto, código y caja, y entrar a JetVenta.
3. Verificar en la caja adicional que no existen los servicios
   `PuntoDeVentaApi` y `PuntoDeVentaPostgreSQL` ni carpetas `api` o
   `postgresql` bajo `C:\Program Files\JetVenta`.
4. Actualizar ambas modalidades y confirmar que se conserva su tipo. La caja
   adicional no debe pedir código de emparejamiento otra vez.
5. Simular un código vencido: la instalación debe quedar pendiente de
   emparejamiento y pedir un código nuevo en la siguiente ejecución.
