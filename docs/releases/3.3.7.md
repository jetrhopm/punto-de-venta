# JetVenta 3.3.7 - Administración y recuperación multicaja

## Implementado

- Administración desde el servidor de cajas activas e inactivas: nombre,
  equipo, última conexión, sesión y turno abierto.
- Renombrado, baja lógica, reactivación y reemparejamiento seguro de cajas.
- Un reemparejamiento conserva la caja existente, invalida sus sesiones y token
  anterior, y genera un código temporal de un solo uso.
- La baja de una caja con turno abierto se rechaza para no dejar efectivo ni
  movimientos sin responsable. La baja no elimina historial, ventas ni
  inventario.
- Diagnóstico según modalidad de instalación. Una caja adicional no intenta
  reparar servicios locales y explica que la administración se hace desde el
  servidor.
- Respaldos, restauración, limpieza de datos y PostgreSQL quedan restringidos a
  la caja principal / servidor.
- Restauración con modo de mantenimiento persistente: mientras la base se
  reemplaza, JetVenta bloquea temporalmente logins y operaciones; al concluir o
  fallar el script libera el estado.

## Migración

`AgregaAdministracionDeCajasYReemparejamiento` añade la referencia opcional de
caja a los códigos de emparejamiento. Los códigos normales continúan creando
una caja nueva; los códigos de reemparejamiento recuperan la caja indicada.

## Pruebas manuales recomendadas

1. En el servidor, abre Configuración > Cajas y equipos con administrador.
2. Verifica que cada caja muestre nombre, estado, equipo, conexión, usuario y
   turno abierto.
3. Intenta desactivar una caja con turno abierto y confirma que JetVenta la
   rechaza sin cambiar datos.
4. Cierra el turno, desactiva y reactiva la caja; confirma que el historial se
   conserva y sólo cambia su disponibilidad para iniciar sesión.
5. Genera un código de volver a emparejar y úsalo en la misma caja adicional.
   Debe conservar el nombre de caja y requerir iniciar sesión de nuevo.
6. En una caja adicional, abre Diagnóstico y Configuración: no deben aparecer
   reparación de API ni administración de respaldos.
7. Inicia una restauración en servidor y confirma que otra caja recibe el aviso
   de mantenimiento hasta que termine el proceso.
