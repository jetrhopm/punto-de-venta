## 2. Cómo funciona hoy (3.3.58)

- **Una compra = un solo producto.** `PurchaseWindow` (sección Compras) selecciona un producto y captura cantidad, costo y precio de venta, y envía `POST /api/purchases/receive` con una sola partida. La API ya acepta varias partidas.
- **Costo.** El costo se recalcula como **promedio ponderado** (existencia anterior × costo anterior + recibido × costo nuevo) / existencia nueva.
- **Precio de venta.** Se guarda el precio escrito en pantalla y el % de ganancia del producto se recalcula a partir de él. No hay ninguna advertencia cuando cambia el costo.
- **Pago desde caja.** Con la casilla marcada, se crea una salida de efectivo `Out` por **el total exacto** con el motivo "Pago a proveedor: {nombre}" en el turno abierto del usuario. No se captura cuánto efectivo se sacó físicamente.
- **Historial.** Se guardan `purchase`, `purchase_line`, `inventory_movement` y `cash_movement`, pero **no existe** ninguna consulta ni pantalla para ver compras anteriores.

## 3. Lo que se pidió (entendimiento)

Un proveedor, por ejemplo Sabritas, entrega varios productos en una sola visita. La recepción debe funcionar como una venta:

1. **Elegir el proveedor** una vez para toda la recepción.
2. **Escanear o buscar productos.** Cada uno se agrega a una **lista**. Si se vuelve a escanear un producto que ya está en la lista, se suma 1 pieza en vez de duplicar la línea.
3. **Columnas de la lista:**
   - descripción;
   - código de barras (numérico);
   - piezas recibidas (editable);
   - precio del proveedor, es decir el costo unitario (editable);
   - precio de venta actual;
   - % de ganancia;
   - importe (piezas × costo).
   - Las flechas ↑/↓ seleccionan, Supr quita la línea y Enter edita, igual que en Ventas.
4. **Precio cuando cambia el costo.** Si el precio del proveedor es distinto al costo registrado, se **advierte** al usuario y se le pregunta:
   - **Actualizar el precio de venta** aplicando el % de ganancia del producto: nuevo precio = costo × (1 + %/100), o
   - **Conservar el precio de venta actual**. En ese caso solo se recalcula el %.

   Para no interrumpir en cada producto, se propone que la pregunta aparezca **al confirmar la recepción**: una sola ventana con la lista de productos cuyo costo cambió, el precio actual, el precio sugerido y una casilla por producto, más los botones "Actualizar todos" y "Conservar todos".
5. **Confirmar la recepción.** Se muestra el total a pagar al proveedor (suma de la lista) y se pregunta si se paga con **efectivo de caja**.
6. **Pago desde caja.** Si se elige, el sistema muestra **cuánto debe pagar** y el cajero **escribe la cantidad que retiró** de la caja, que se registra como salida de efectivo, para que el conteo del corte cuadre con lo que realmente salió.
7. **Resultado.** Se registra **una sola compra** con todas sus partidas, entradas de inventario por cada producto y, si aplica, una sola salida de caja.

## 4. Plan técnico propuesto

### API / Infraestructura
- **`ReceivePurchaseCommand`**
  - Se agrega `CashWithdrawn` (decimal opcional, el efectivo retirado).
  - Cada partida lleva una decisión de precio: `KeepSalePrice` o `ApplyProfitPercent`, o el `SalePrice` ya calculado.
- **`SupplierPurchaseService.ReceiveAsync`**
  - Valida que no haya productos duplicados en la lista.
  - Aplica la decisión de precio por partida.
  - Registra la salida de caja por `CashWithdrawn`.
  - Guarda el total y el monto retirado en `purchase`.
- **Migración** `AgregaEfectivoRetiradoEnCompra`: agrega la columna `purchase.cash_withdrawn` (numeric 18,2, nullable).
- **Corte.** Los pagos a proveedor se muestran desglosados dentro de las salidas, por ejemplo "Pagos a proveedores: $X". No cambia la fórmula del efectivo esperado.

### Escritorio
- **`PurchaseWindow`.** Se rediseña con proveedor arriba, caja de escaneo/búsqueda, lista editable de productos, total y botón **Confirmar recepción**. La lista no se pierde al cambiar de sección mientras la ventana siga abierta.
- **Ventana de precios.** Una ventana nueva, `PurchasePriceReviewWindow`, presenta los cambios de costo con la opción de actualizar el precio por % o conservarlo.
- **Ventana de pago.** Una ventana nueva, `PurchaseCashPaymentWindow`, muestra el total a pagar y captura el monto retirado.
- **Atajos de teclado.** Mismo manejo de teclado que Ventas F1.

### Fuera de alcance (siguiente paso sugerido)
- Pantalla de **historial de compras**, con filtros por fecha, proveedor, empleado y pagado desde caja.

## 5. Decisiones confirmadas (2026-10-10)

1. **El efectivo retirado puede ser distinto del total y no se bloquea.** Puede que el gerente u otra persona haya pagado, o que el proveedor haya regalado mercancía que no debe contarse como retiro.
   - La salida de caja es **por lo que el cajero dice que retiró**, que puede ser $0.
   - En la compra se guardan el total, el monto retirado y una nota opcional.
2. **El costo se sigue promediando** (promedio ponderado). Cuando el precio del proveedor cambia, se **pregunta** al usuario si ajusta el precio de venta con el % o sigue vendiendo con el mismo precio.
   - **Regla obligatoria:** el precio de venta **nunca puede quedar por debajo del precio del proveedor**. La API lo rechaza y la pantalla no deja confirmar.
3. **Orden de prioridad para calcular el precio de venta:**
   1. Si el producto tiene **% de ganancia**, el precio sugerido es costo promedio nuevo × (1 + %/100). El usuario decide si actualiza o conserva el precio.
   2. Si **no tiene %** pero sí precio de venta, se **conserva el precio de venta**.
   3. Si **no tiene precio de venta**, se calcula con el **% general del sistema** (`DefaultProfitPercent`).
   4. Si **no hay ninguno**, se **pide al usuario** el % o el precio de venta.
4. **El código puede ser alfanumérico.** La lista muestra el código tal cual y no se generan códigos de barras en este flujo.
5. **El proveedor es opcional también al pagar con caja** (cambio de la tarde del 2026-10-10). Antes se exigía para registrar el retiro; ahora se permite "Sin proveedor" y la ventana de pago sugiere elegirlo o explicar en la nota qué se compró.
6. **Historial de compras a proveedores por cajero.** Se consulta desde Compras con filtros de fecha, cajero, proveedor y "solo pagadas con efectivo de caja", y muestra el detalle de productos de cada compra.

## 6. Implementación

### API / Infraestructura
- **`PurchaseLineCommand`**
  - Se agrega `ProfitPercentToApply` (opcional). Si viene, el precio = costo promedio nuevo × (1 + %/100) y se guarda ese %.
  - Si en su lugar viene `SalePrice`, se usa ese precio y el % se recalcula.
  - Si no viene ninguno, el precio no cambia.
- **`ReceivePurchaseCommand`**
  - Se agregan `CashWithdrawn` (opcional; si se paga desde caja y no viene, se usa el total, que es el comportamiento anterior) y `Notes`.
- **Validaciones nuevas:**
  - no se permiten productos repetidos en una misma compra;
  - el precio de venta final debe ser mayor o igual al precio del proveedor;
  - el monto retirado no puede ser negativo.
- **Migración** `AgregaEfectivoRetiradoEnCompra`: agrega `purchase.CashWithdrawn` (numeric 18,2, nullable) y `purchase.Notes` (varchar 300, nullable).
- **Endpoints nuevos:**
  - `GET /api/purchases`, con filtros `from`, `to`, `userId`, `supplierId` y `paidFromCash`;
  - `GET /api/purchases/{id}`, con el detalle de productos;
  - `GET /api/purchases/cashiers`;
  - `GET /api/purchases/pricing-defaults`, que devuelve el % general.
- **Corte.** `CashCutSummary` agrega `SupplierPayments`, la suma de las salidas "Pago a proveedor". No cambia la fórmula del efectivo esperado.

### Escritorio
- **`PurchaseWindow`.** Lista de recepción: escanear o Enter agrega el producto, un escaneo repetido suma una pieza, y las piezas y el precio del proveedor se editan en la misma lista. Teclado: ↑/↓ seleccionan, Supr quita la línea con la búsqueda vacía, y Enter con la búsqueda vacía edita las piezas.
- **`PurchasePriceReviewWindow`.** Muestra los productos cuyo precio debe decidirse: actualizar con %, conservar el precio o capturar un precio manual. Tiene botones para aplicar la misma decisión a todos y bloquea los precios menores al precio del proveedor.
- **`PurchasePaymentWindow`.** Muestra el total a pagar y pregunta si sale dinero de caja, cuánto se retiró y una nota opcional.
- **`PurchaseHistoryWindow`.** Historial por cajero con filtros, totales y detalle de cada compra.
- **`CutWindow`.** Muestra "Pagos a proveedores" dentro de las salidas.
